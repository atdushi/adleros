# 📉 AdlerOS v9.0

> **AdlerOS** — экспериментальный рантайм на платформе **.NET 9.0** и **C# 13**, реализующий принципы Индивидуальной психологии Альфреда Адлера через строгое объектно-ориентированное программирование.

В отличие от систем, завязанных на либидо или базальную тревогу, AdlerOS работает на движке **компенсации комплекса неполноценности**. Цель рантайма — направить врожденное стремление к превосходству в конструктивное русло, развивая социальный интерес (Gemeinschaftsgefühl) и решая жизненные задачи без ухода в невротическую изоляцию. Визуализировано с помощью **Spectre.Console**.

---

## 🔬 Теоретический Фундамент и Архитектура

Архитектура AdlerOS построена вокруг концепции, что главным стимулом развития системы является её «недостаточность» (Organ Inferiority / Базовая неполноценность). Система постоянно пытается преодолеть этот дефицит.

### Ключевые Метрики Системы (State Ресурсы)

* `_inferiorityIndex` — Индекс Неполноценности. Главное топливо и мотиватор рантайма. Рост выше 80% активирует *Комплекс Неполноценности* и парализует выполнение задач. Снижение до 0% лишает систему стимула к эволюции.
* `_socialInterest` — Социальный Интерес. Маркер психического здоровья. Показывает, насколько эффективно система сотрудничает с другими узлами, не уходя в эгоцентрическое превосходство.

### Анатомия Кодовой Базы

* **`AdlerianMind.cs`** — Ядро личности. Инкапсулирует приватные метрики и пропускает социальные задачи через установленный Стиль Жизни.
* **`IStyleOfLife.cs`** — Интерфейс Стиля Жизни. Паттерн **Strategy**. Определяет, каким образом ядро реагирует на внешние вызовы (работа, дружба, любовь).
* **`FictionalFinalismDecoder.cs`** — Декоратор Фиктивного Финализма. Перехватывает векторы компенсации и может увести систему в деструктивную *Сверхкомпенсацию* ради иллюзии абсолютного превосходства.
* **`AdlerianDelegates.cs`** — Кастомный `CompensationDelegate`, легально передающий приватные метрики ядра по ссылке (`ref double`) для их глубокой трансформации.

## 🛤️ Паттерн Strategy: Стили Жизни (`IStyleOfLife`)

В зависимости от текущей конфигурации, ядро обрабатывает задачи одним из следующих паттернов:

| Стиль Жизни | Класс | Поведение в коде | Трейд-офф |
| :--- | :--- | :--- | :--- |
| **Управляющий** *(Ruling)* | `RulingStyle.cs` | Решает задачи через доминирование, подавление чужих интерфейсов и потоков. | `_socialInterest` стремительно падает |
| **Социально-полезный** *(Useful)* | `SociallyUsefulStyle.cs` | Здоровая интеграция. Решает задачи через кооперацию, рефакторинг и взаимопомощь. | Идеальный баланс метрик |

## 🏃‍♂️ Быстрый запуск

Скомпилируйте проект и запустите симуляцию индивидуального стиля жизни:

```bash
dotnet run --project src/AdlerOS.csproj
```

### Пример инициализации и компенсации через `ref`-делегаты

```csharp
using AdlerOS.Core;
using AdlerOS.Strategies;
using AdlerOS.Decorators;

// 1. Создаем ядро личности
var mind = new AdlerianMind();

// 2. Устанавливаем социально-полезный стиль жизни для решения задач
mind.SetStyleOfLife(new SociallyUsefulStyle());
mind.ExecuteSocialTask("Дедлайн по рефакторингу legacy-модуля");

// 3. Подключаем Фиктивный Финализм для компенсации неполноценности
var finalism = new FictionalFinalismDecoder();

// Передаем метод компенсации как делегат, оперирующий ref-полями
mind.Compensate(finalism.Overcompensation);
```

## 🤝 Contribution Guidelines (Социальный Контрибьютинг)

Разработка AdlerOS базируется на высоком уровне Социального Интереса. PR принимаются только в том случае, если они приносят пользу всему сообществу:

1. **Запрет на Управляющий Тип в PR:** Pull Request'ы, которые переписывают чужие модули без обсуждения, содержат токсичные комментарии или пытаются доминировать в архитектуре, будут закрыты. Ваш личный индекс неполноценности при этом будет принудительно поднят до 99%.
2. **Запрет на бегство в болезнь (Organ Inferiority):** Коммиты с описанием `"исправил какой-то баг, потому что у меня не работал компилятор и вообще всё плохо"` отклоняются. Ошибки сборки — это не повод для жалости рантайма, а стимул к здоровой компенсации через чтение логов.
3. **Общность интерфейсов:** Любой новый Свойство или Метод должен иметь высокий уровень зацепления (Cohesion) и служить целям интеграции, а не обособления. Мы строим распределенную систему, а не изолированный монолит.
